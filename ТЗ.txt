ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) — Версия 1.2 (Оптимизированная)

Название проекта: Sentinel-RS (eBPF Desktop Anti-Stealer & AI Triage)
Назначение: Гибридный хостовый защитник / фаервол для Linux Desktop, выявляющий инфостилеры и вредоносную эксфильтрацию данных с семантическим анализом через локальный ИИ, с поддержкой управления через CLI и легковесный GUI.

1. Аппаратно-программные требования стенда
ОС: Debian 13 (Trixie), ядро Linux 6.x+ (CONFIG_DEBUG_INFO_BTF=y, eBPF LSM).
Аппаратная платформа: Samsung NP300E5A (Intel Core i3/i5 2nd gen, RAM 4–8 GB).
Специфика CPU: Сборка компонентов ИИ и GUI без AVX2 (строго SSE4.2 / AVX-1).
Потребление ресурсов: Фоновый демон < 50 МБ RAM, GUI в свернутом виде < 30 МБ RAM. Никакого Electron!
Фоллбэк: Поддержка Graceful Degradation (переход на cgroups/tracepoints при отсутствии активного LSM BPF).

3. Функциональные требования

3.1. Ядровый уровень (eBPF)
1. Taint Tracking и App Scoping (Владелец секрета):
   - Отслеживание обращений к защищаемым директориям:
     * Telegram Desktop (`*/tdata/*`) — разрешено только бинарнику Telegram.
     * Браузеры Chrome/Chromium/Firefox (`*/Cookies`, `*Login Data*`, `*places.sqlite*`) — разрешено только соответствующим браузерам.
     * Ключи и кошельки (`~/.ssh/*`, `~/.gnupg/*`, `~/.config/Exodus/*`) — доступ только явно авторизованным процессам.
   - Если неавторизованный процесс читает защищаемый путь — маркировка флагом TAINTED в eBPF Map.
2. Taint Inheritance (Наследование заражения):
   - Хук `sched/sched_process_fork`: при порождении дочерних процессов (`fork`, `clone`) флаг TAINTED автоматически наследуется дочерними PID/TGID, предотвращая обход через spawn подпроцессов.
3. Сетевой перехват и блокировка (Non-blocking Network Drop):
   - Проверка флагов процесса при вызове `lsm/socket_connect` (IPv4, IPv6, Unix domain).
   - При наличии флага TAINTED ядро немедленно блокирует соединение, возвращая `-EPERM` или `-ECONNREFUSED`.
   - Процесс НЕ замораживается наглухо через `SIGSTOP`, что устраняет зависания рабочего стола и GUI. Пакет гарантированно не уходит в сеть.
   - Блокировка DNS-эксфильтрации: при флаге TAINTED блокируются исходящие обращения на порт 53 и к локальному сокету `127.0.0.53:53` (systemd-resolved) до верификации.

3.2. Демон (`sentineld`, Rust)
1. Двухуровневый движок вердиктов (Tiered Engine):
   - Уровень 1: Fast Heuristics (Быстрые статические правила, 0 мс):
     * Анализ источника запуска: запуск из `/tmp`, `/dev/shm`, `~/.cache`, скрытых папок.
     * Анализ окружения: отсутствие TTY, замаскированное имя, аномальное дерево процессов.
     * Если совпадение 100% (явный вредоносный стилер) -> мгновенный `kill(pid, SIGKILL)` без ожидания нейросети.
   - Уровень 2: Local AI Triage (Qwen 2.5 0.5B/1.5B):
     * Применяется только для «серой зоны» (пограничные и неясные запуски).
     * Роль модели: семантический аудит и формирование понятного человекочитаемого отчёта об инциденте для пользователя (Explaining AI Assistant), а не слепой палач.
2. Whitelist и проверка целостности (Integrity Checker):
   - Белый список оперирует не только путями, но и хэшами SHA-256 исполняемых файлов (`/proc/<PID>/exe`).
   - Кэширование хэшей для исключения оверхеда при повторных запусках.
   - Интеграция с базой пакетов Debian (`dpkg -V`) для подтверждения неизменности системных утилит.
3. IPC Сервер:
   - Обмен командами и событиями через Unix Domain Socket (`/run/sentinel.sock`) с разграничением прав доступа.

3.3. Управление через терминал: CLI (`sentinelctl`)
Консольная утилита для опытных пользователей, скриптов и быстрой настройки.
Синтаксис команд:
- `sentinelctl status` — текущее состояние защиты (активен/пауза, статус ИИ-движка, количество заблокированных угроз).
- `sentinelctl monitor` — TUI-режим онлайн-стриминга событий: в реальном времени показывает, какие процессы трогают сеть и файлы.
- `sentinelctl whitelist add <путь>` — добавить бинарник в исключения с автоматическим расчётом SHA-256.
- `sentinelctl whitelist list` — показать текущий белый список и хэши.
- `sentinelctl mode [strict | balanced | learning]` — переключение режима:
  * strict (параноик): строгая изоляция любых несанкционированных чтений.
  * balanced (дефолт): фокус на инфостилерах и эксфильтрации с двухуровневой фильтрацией.
  * learning (обучение): профилирование софта и бэкапов без блокировки.
- `sentinelctl unfreeze <PID>` — снять сетевые ограничения с ложно помеченного процесса.

3.4. Минималистичный GUI (`sentinel-gui`, Slint)
- Стек: Rust + Slint (нативный, сверхлегкий; потребление < 30 МБ RAM).
- Главный экран («Щит»):
  * Индикатор безопасности (Зеленый щит / Обнаружена угроза).
  * Тумблер [ Вкл / Выкл Защиту ].
  * Режим чувствительности (Обычная / Умная / Параноик).
  * Карточка с понятным объяснением от ИИ простым языком, если был перехвачен подозрительный процесс.
- Вкладка «Что защищать» (Категории: Telegram, Браузеры, SSH, Крипта).
- Вкладка «Белый список» (Карточки доверенных программ с проверкой хэшей).
- Системный трей: статус, быстрая пауза на 15 мин, быстрый переход к дашборду.

3.5. Инсталляция и системная интеграция
- Поставка в `.deb`-пакете:
  * `postinst`-скрипт автоматически проверяет статус `lsm=bpf` в `/sys/kernel/security/lsm`. При отсутствии — автоматически добавляет параметр в `/etc/default/grub` и вызывает `update-grub`.
  * Установка systemd-юнита (`sentineld.service`).

4. Технологический стек
| Направление | Инструмент / Библиотека | Преимущество |
|-------------|-------------------------|--------------|
| Ядро | Aya-bpf (Rust) | Безопасная разработка eBPF без C-зависимостей |
| Демон | tokio + clap + sha2 (Rust) | Асинхронный сервер, быстрый CLI, проверка хэшей |
| IPC | interprocess / Unix Sockets | Быстрое общение между root-демоном и GUI |
| AI Inference | llama-cpp-rs (Qwen 2.5) | Быстрый инференс на CPU с AVX-1 / SSE4.2 |
| GUI | Slint UI (Rust) | Ультралегкий нативный интерфейс (< 30 МБ RAM) |
| Алерты | notify-rust (D-Bus) | Нативные всплывающие окна среды рабочего стола |
