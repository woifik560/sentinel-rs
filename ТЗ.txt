ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) — Версия 1.1

Название проекта: Sentinel-RS (eBPF Desktop Anti-Stealer & AI Triage)
Назначение: Гибридный хостовый защитник / фаервол для Linux Desktop, выявляющий инфостилеры и вредоносную эксфильтрацию данных с семантическим анализом через локальный ИИ, с поддержкой управления через CLI и легковесный GUI.

1. Аппаратно-программные требования стенда
ОС: Debian 13 (Trixie), ядро Linux 6.x+ (CONFIG_DEBUG_INFO_BTF=y, eBPF LSM).
Аппаратная платформа: Samsung NP300E5A (Intel Core i3/i5 2nd gen, RAM 4–8 GB).
Специфика CPU: Сборка компонентов ИИ и GUI без AVX2 (строго SSE4.2 / AVX-1).
Потребление ресурсов: Фоновый демон < 50 МБ RAM, GUI в свернутом виде < 30 МБ RAM. Никакого Electron!

3. Функциональные требования
3.1. Ядровый уровень (eBPF)
Taint Tracking (отслеживание кражи):
Фиксация обращений к критическим директориям:
Telegram Desktop (*/tdata/*)
Браузеры Chrome/Chromium/Brave/Firefox (*/Cookies, *Login Data*, *places.sqlite*)
Ключи и кошельки (~/.ssh/*, ~/.gnupg/*, ~/.config/Exodus/*)
Маркировка процесса флагом TAINTED в eBPF Map.
Сетевой перехват:
Проверка флагов процесса при вызове sys_enter_connect / lsm/socket_connect.
При совпадении с TAINTED — отправка события в Userspace и блокировка трафика.
3.2. Демон (sentineld, Rust)
Изоляция: Моментальная отправка kill(pid, SIGSTOP) процессу-нарушителю до получения вердикта от ИИ или пользователя.
AI-анализ: Инференс локальной модели Qwen 2.5 0.5B (парсинг: кто запустил, что прочитал, куда ломится).
IPC Сервер: Обмен командами и событиями через Unix Domain Socket (/run/sentinel.sock) с разграничением прав.
3.3. Управление через терминал: CLI (sentinelctl)

Консольная утилита для опытных пользователей, скриптов и быстрой настройки.

Синтаксис команд:

sentinelctl status — текущее состояние защиты (активен/пауза, статус ИИ-движка, количество заблокированных угроз).
sentinelctl monitor — TUI-режим онлайн-стриминга событий: в реальном времени показывает, какие процессы трогают сеть и файлы.
sentinelctl whitelist add <путь_к_бинарнику> — добавить процесс в исключения (например: sentinelctl whitelist add /usr/bin/curl).
sentinelctl whitelist list — показать текущий белый список.
sentinelctl mode [strict | balanced | learning] — переключение режима:
strict (параноик): ИИ блокирует любые отклонения.
balanced (дефолт): фокус строго на инфостилерах и краже секретов.
learning: только запись логов без реальной блокировки (для сбора профиля софта).
sentinelctl unfreeze <PID> — разморозить ошибочно заблокированный процесс (SIGCONT).

Файл конфигурации (/etc/sentinel/config.toml):

toml
[general]
mode = "balanced"            # strict | balanced | learning
ai_enabled = true
auto_kill_score = 90         # Убивать процессы с риском >90 без лишних вопросов
[targets]
protect_telegram = true
protect_browsers = true
protect_ssh = true
protect_crypto = true
[whitelist]
binaries = [
    "/usr/bin/apt",
    "/usr/lib/firefox/firefox"
]
3.4. Минималистичный GUI (sentinel-gui)

Целевая аудитория интерфейса: Начинающие пользователи Linux, которым не нужны сложные деревья процессов и консольные флаги.
Стек интерфейса: Rust + Slint (нативный, сверхбыстрый тулкит; бинарник весит ~10 МБ, запускается за 0.05 секунды даже на слабом CPU).

Концепция экрана (Всего 3 вкладки):

Главный экран («Щит»):

Огромный статус-индикатор: «Система защищена» (Зеленый щит) / «Обнаружена угроза» (Красный).
Главный тумблер: [ Вкл / Выкл Защиту ].
Ползунок «Чувствительность ИИ»:
🟢 Обычная (спрашивать только при явной краже паролей)
🟡 Умная (рекомендуется)
🔴 Максимальная (проверять любой новый запуск из Downloads/tmp)
Индикатор: «Использовано памяти: 380 МБ (AI Ready)».

Вкладка «Что защищать» (Простые чекбоксы):

[x] Сессии Telegram и Discord
[x] Пароли и куки браузеров (Chrome, Firefox)
[x] SSH-ключи и системные токены
[ ] Криптокошельки (Exodus, Electrum)

Вкладка «Белый список» (Исключения):

Список разрешенных программ в виде карточек с иконками.
Большая кнопка: [ + Добавить программу в исключения ] (открывает стандартный диалог выбора файла).

Системный трей (System Tray):

Висит в панели задач рядом с часами.
По клику правой кнопкой: «Приостановить на 15 минут», «Открыть дашборд», «Выход».
4. Технологический стек
Направление	Инструмент / Библиотека	Почему именно это
Ядро	Aya-bpf (Rust)	Без C-зависимостей, работа с eBPF нативно
Демон	tokio + clap (Rust)	Быстрый асинхронный сервер и удобный CLI-парсер
IPC	interprocess / Unix Sockets	Быстрое общение между root-демоном и пользовательским GUI
AI Inference	llama-cpp-rs (C++ bind)	Максимальный FPS на Intel Sandy Bridge (AVX-1, без AVX2)
GUI	Slint UI (Rust)	Не жрёт память в отличие от Electron/Python, взлетает мгновенно
Алерты	notify-rust (D-Bus)	Стандартные системные окна поверх экрана
5. Пошаговый план разработки (Roadmap)
 Этап 1: Подготовка стенда и тесты на CPU
Включение lsm=bpf в Debian 13.
Сборка тестового бинарника с Qwen2.5-0.5B и замер времени инференса (цель: JSON-ответ быстрее 2 секунд).
 Этап 2: Ядро и демон eBPF (Бэкэнд)
Реализация lsm/file_open для детекта чтения .ssh / tdata.
Реализация lsm/socket_connect для перехвата сетевого сокета.
Реализация заморозки через SIGSTOP.
 Этап 3: IPC и Консольный клиент (sentinelctl)
Создание Unix-сокета /run/sentinel.sock.
Реализация базовых CLI-команд: status, whitelist, mode.
 Этап 4: Интеграция ИИ-триажа
Автоматическая передача структурированного контекста нарушителя в локальную модель.
Получение вердикта и автоматический SIGKILL, если риск > 90%.
 Этап 5: Минималистичный GUI (sentinel-gui) на Slint
Верстка интерфейса из 3 вкладок.
Связка GUI с демоном через Unix-сокет.
Интеграция системного трея.
 Этап 6: Стендовое тестирование
Тест на вредоносном скрипте: проверка отработки CLI, вывода GUI-уведомления и блокировки сокета.
